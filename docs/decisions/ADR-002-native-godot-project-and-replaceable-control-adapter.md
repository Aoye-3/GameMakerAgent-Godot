# ADR-002：原生 Godot 项目是真实源，MCP 位于可替换控制适配层

## 状态

Accepted

## 日期

2026-08-31

## 背景

VibeGame 已有基于浏览器/Phaser 的 RuntimeBridge、输入控制、结构化快照和证据审查。
Godot 自身已经提供原生项目、场景、资源、导入和调试模型。把这些模型重新包成一套
平行引擎会增加维护成本，也会限制 Godot 能力。

开源 Godot MCP 的能力和成熟度仍在快速变化，因此框架不能把 Agent 协议直接绑定到
某一个服务器的工具名称。

## 决策

1. TapTapGameJam 中的原生 Godot 项目是代码、场景和资产的真实源。
2. 普通文本代码和资源优先使用文件系统编辑；复杂 Godot 序列化操作可通过编辑器 API。
3. MCP 用于运行生命周期、输入、确定性推进、语义状态、截图、信号和诊断等控制面能力。
4. GameMakerAgent 定义引擎中立的 Runtime Adapter；具体 MCP 实现在适配器之后。
5. 第一阶段先以同一场景实测现有 MCP，只有明确能力或安全缺口才自研服务器。

## 备选方案

### 所有文件经 MCP 传输

会重复本地文件能力、削弱 Git diff 并增加上下文成本，拒绝。

### 将 VibeGame 引擎 API 完整映射到 Godot

会在 Godot 之上重建场景、资源和物理模型，拒绝。只复用 Agent、契约和证据闭环。

### 立即自研全功能 Godot MCP

在最高风险的运行验证尚未证明前投入过大，拒绝。

## 后果

- Runtime Adapter 和 Evidence Bundle 成为首批稳定契约。
- MCP 可以更换，但更换必须通过相同契约测试。
- 截图不能作为唯一证据；结构化状态、输入轨迹和诊断必须可关联到同一运行时刻。
- 任意脚本执行和运行时写入必须有显式权限与审计记录。
